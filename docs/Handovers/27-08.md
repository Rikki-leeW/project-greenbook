==================================================
WHAT SPRIG IS
==================================================

Sprig is a personal gardening chronicle and garden intelligence app.

It is not meant to feel like:
- agricultural management software
- a laboratory database
- generic inventory software
- a sterile productivity dashboard

It should feel like a beautiful, useful, long-lived garden notebook that happens to have a strong relational data model underneath it.

The visual identity is:
- woodland
- botanical
- old garden journal / field notebook
- warm
- tactile
- elegant
- slightly whimsical without becoming childish
- practical
- timeless

Sprig language should feel human and garden-oriented rather than clinical.

Examples of our language:
- Plant Stories rather than generic plant records
- Garden Chronicle / Journal
- Growing Places
- Growing Recipes
- Garden Trials rather than scientific experiments
- “Quietly unfolding” for an in-progress garden trial
- “Story gathered” for completed
- “Thrived”
- “Didn’t take”
- Satchel for navigation/menu
- “What Sprig remembers”
- “Where this story reaches”

Avoid turning Sprig into twee/cutesy gardening software. It can have charm without talking to the gardener like a child.

RECENT MAJOR ARCHITECTURE ISSUE:
GROWING MIX / INGREDIENT / PRODUCT MODEL
==================================================

This is the feature we are actively working on NOW.

The original real-world problem:

On a fresh PC/new garden, while creating/editing a Plant and making an own Growing Recipe, I discovered I could not properly add a bought soil/potting mix to the recipe.

Historically:
- Products lacked a sensible soil/potting-mix category
- Ingredients lacked an appropriate category
- “Add a new ingredient” only created Ingredient
- existing bought mixes could be represented elsewhere as Growing Recipes
- this risked duplicating the same real item into several record types

We decided this was fundamentally an architecture problem, not merely a missing dropdown option.

CORE DECISION:

An Ingredient stays an Ingredient.
A Product stays a Product.
A Bought Mix stays a Growing Recipe.
A My Recipe stays a Growing Recipe.

ANY of these may be a COMPONENT of another Growing Recipe.

Do not create shadow duplicate records just to make another recipe able to reference them.

Example:

If “Basics Tomato and Vegetable Growing Mix” already exists in Sprig as a GrowingSetup with category bought-mix, and I use it as part of “My Potato Mix”, My Potato Mix should LINK TO that existing GrowingSetup.

It should NOT create:
- a duplicate Ingredient
- a fake Product
- another copy of the bought mix

The relationship is the important thing.
