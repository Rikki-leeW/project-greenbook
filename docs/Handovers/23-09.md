## 2. What Garden of Mine is

Garden of Mine is a personal botanical chronicle and garden-memory application.

It is not:

- Farm-management software
- An accounting application
- A generic CRUD dashboard
- A spreadsheet
- A clinical horticultural database
- A childish gardening game

It should feel like an old gardener’s notebook inside a warm woodland world: personal, calm, botanical, tactile, thoughtful and quietly magical.

Sprig is the garden helper and keeper of the gardener’s recorded story.

> You grow the garden. Sprig keeps the story.

The product is **Garden of Mine**, abbreviated **GOM**. Do not call it “My Own Garden” or “MOG.”

## 3. Core product principles

Preserve these established principles:

- Purpose determines presentation.
- Relationships determine memory.
- Cards are for decisions; pages are for reading.
- Back remembers the journey; Home remembers where the record lives.
- Records own photographs; relationships gather the story.
- Derive known context; do not ask twice.

- Quick Add means a quick journey, not cheap data.

- Sprig must not claim evidence the gardener has not recorded.

## 4. Technical architecture

The application uses:

- React

- Elegant readable serif typography

## 8. CSS ownership rules

This is critical.

### Global foundations

- `src/css/base/index.css`
- `src/css/base/variables.css`

These own resets, tokens and application-wide foundations.

### Stylesheet composition

- `src/css/App.css`

This owns imports and shared application composition. It should not become a dumping ground for component styling.

### Shared layout

- `src/css/components/layout.css`

Owns shared page geometry, headers, journey navigation and Back to Top placement.

### Navigation

- `src/css/components/navigation.css`

Owns shared application navigation and Satchel presentation.

### Buttons

- `src/css/components/buttons.css`

Owns what ordinary shared buttons, tabs and selectable chips look like, including:

- Default appearance
- Hover
- Focus
- Active
- Selected
- Disabled states

Page CSS may position a button but must not redefine its intrinsic visual appearance.

### Uniform controls

- `src/css/components/uniform-controls.css`

Should own common form controls:

- Inputs
- Selects
- Textareas
- Checkboxes
- Radios
- Shared field behaviour
- Mobile text-entry sizing

It must not duplicate action-button, tab or chip appearance owned by `buttons.css`.

### Forms

- `src/css/components/forms.css`

Owns notebook form presentation and form layout—not shared button appearance.

### Plant Cards

- `src/css/cards/plantcard.css`

Must own all intrinsic Plant Card styling:

- Card surface
- Borders and shadows
- Plant name
- Age
- Planted line
- Latest activity line
- Rich details
- Status pill inside the Plant Card
- Thumbnail
- Open Story action
- Selection/comparison states
- Plant Card responsive rules

`plants.css` must not contain a second competing copy of Plant Card appearance.

### Plants page

- `src/css/pages/plants.css`

Owns Plants-page composition:

- Page artwork and atmosphere
- Header placement
- Search/filter-panel placement
- Plant grid
- Comparison-area placement
- Sprig Noticed layout
- Responsive page structure

It may position Plant Cards but must not restyle their intrinsic component appearance.

### Feature styles

Other page and feature stylesheets own only their feature-specific content and composition.

The permanent rule is:

> A page decides where a component goes. The component stylesheet decides what the component looks like.

## 11. Current button bug and intended fix

The selected green controls were affected by competing CSS:

- “Growing now” could turn white on hover while its text remained white.
- The selected “days” chip could also turn white.
- A later attempt caused a brief flash/disappearance before the control returned to the original appearance.

This confirmed that multiple stylesheets were competing.

The permanent solution is:

- `buttons.css` owns the complete appearance and interaction states for:
  - `.plant-story-view-tab`
  - `.plant-filter-chip`
- Selected controls must remain green with readable white text during hover, focus and active states.
- Hover must not cause layout movement, disappearance, flashing or colour inversion.
- `uniform-controls.css` should retain only field/control foundations and no competing appearance rules for those button classes.
- `plants.css` may own the layout of the tab/chip groups, but not their colours or interactive states.

Do not fix this with another higher-specificity page override. Remove the conflicting owner.
